# 논문 근거에서 카드뉴스까지 — 운영 절차

## 운영 방식 선택
| 방식 | 사용 상황 | 장점 | 실제 부담 |
|---|---|---|---|
| ChatGPT 조사 + Codex 제작 | 수술 후 재활, 복귀 판단, 위험 수치, 사용자의 필수 의견이 있는 주제 | 대화로 연구 해석과 메시지를 먼저 조정 | 연구 파일을 전달해야 함 |
| Codex 안에서 순차 실행 | 논문 PDF와 근거가 준비됐고 반복 제작할 때 | 파일 기록과 제작 흐름이 이어짐 | 원문/검색 권한 확인 필요 |
| Codex 조사 + 중요한 주장만 별도 검토 | 제작량이 늘었을 때 | 검토 범위를 좁힘 | 별도 검토도 독립적으로 원문 위치를 확인해야 함 |

현재 권장: 첫 번째. 어떤 제품이 항상 더 정확하다는 주장은 아니다.
심층리서치는 여러 연구 비교에 활용하고, 단일 업로드 PDF 정리에는 일반 파일 분석 대화를 사용할 수 있다. 기능 제공 여부는 현재 계정에서 확인한다.

## 상태와 이동 조건
| 상태 | 만든 파일 | 다음 상태 조건 |
|---|---|---|
| INPUT | brief.md, user_notes.md | 질문·대상·필수 의견이 명시됨 |
| RESEARCH_DRAFT | sources.md, claims.md | 검색·접근 범위 기록 |
| RESEARCH_READY | research_brief.md, evidence_review.md | 채택 주장에 출처와 위치가 연결되고 미해결 BLOCK 없음 |
| CONTENT_DRAFT | storyboard.md | 카드마다 실제 게시 문장과 근거가 있음 |
| CONTENT_CONFIRMED | approval_log.md | 사용자의 내용 확정 또는 해당 범위 사전 허용을 기록 |
| DESIGN_DRAFT | source/, assets/, exports/ | 실제 개별 카드 파일 생성 |
| QA_PASSED | QA_REPORT.md, caption.md | 문장·수치·이미지·모바일·파일 검수 통과 |
| BLOCKED | evidence_review.md 또는 QA_REPORT.md | 결함 위치 기록, 해당 부분 수정 후 원래 단계로 복귀 |

`RESEARCH_READY`는 내부 기술 검증 상태다. 사용자의 내용 확정과 같지 않다.
LLM이 스스로 쓴 ‘검토 완료’는 원문 확인이나 외부 전문가 검토를 의미하지 않는다.

## 1. 사용자 입력
- 현재 독자가 궁금한 한 가지 질문
- 대상: 성인/유소년, 진단/수술, 회복 단계, 종목
- 사용자가 넣고 싶은 내용: 결론으로 간주하지 말고 가설/관찰/필수 질문으로 기록
- 기존 글과 겹치지 않을 포인트
- 피해야 할 표현, 장수(기본 6장), 원하는 행동
필수 의견은 U01…로 식별하고 채택/조건부 반영/근거 부족/범위 밖을 기록한다.

## 2. 연구
가이드라인·합의문·공식 프로토콜 → 인용 원문 → 추가 연구 순서.
지침이 없으면 검색 범위를 적고 직접 관련 문헌고찰/연구로 보완한다.
DOI/PMID/제목/출판사 링크로 확인한다. 접근 불가 시 PMC, 기관 리포지터리, 저자 공개본, Unpaywall, Scholar의 합법적 공개본을 찾는다. 검색 도구가 없으면 업로드 자료만 분석하고 최신성 미검증을 표시한다.

각 S ID에 연구 설계, 대상, 표본, 중재/비교, 결과 지표, 기간, 실제 수치, 한계, 확인 범위와 날짜를 적는다.
‘원문 전체 접근 가능’과 ‘Methods/Results/특정 표를 실제 확인’은 별도로 적는다.
논문별 원문 발췌는 위치를 찾는 데 필요한 짧은 구절만 보관하고 결과는 한국어로 다시 설명한다.

## 3. 주장 검증
모든 의학적 주장과 수치에 C ID 부여.
채택 상태: VERIFIED(해당 표현 확인), REVISE(표현/근거 수정), BLOCK(게시 불가).
VERIFIED는 높은 근거 확실성을 뜻하지 않는다. 소규모·관찰·간접·초록만 등의 한계는 별도로 설명한다. 공식 GRADE가 없으면 임의 등급을 만들지 않는다.

수치마다 대상, 분모, 단위, 비교군, 시점, 효과 크기/불확실성, 출처 표/절을 확인한다.
RR/OR/HR을 서로 바꾸지 않는다. 가능한 절대위험을 함께 검토하되 분모가 없으면 역산해 만들지 않는다.
연구 결과 / 연구에 사용된 프로토콜 / 지침 권고 / 임상 제안 / 검증 계산을 구분한다.
관련성 → 인과, 기전 → 임상 효과, 성인 → 유소년, 특정 검사 → 다른 검사로 확장하지 않는다.
상충된 연구는 대상·방법·결과 차이를 비교한다.

사용자 필수 의견도 같은 검증을 받는다. 근거 부족이면 단정문 대신 질문·관찰로 표시하거나 제외 사유를 남긴다.
새 문헌을 추가하면 sources → claims → review → research_brief 순서로 갱신한다. Research Brief만 고쳐 근거 원장을 남겨두지 않는다.

## 4. 제작용 근거 요약
Research Brief에는 다음을 압축한다.
- 독자/질문/한 문장 결론
- 채택할 3~5개 핵심 메시지
- 사용자 필수 의견 반영표
- C ID와 S ID, 허용 문장, 필수 조건, 금지 단정
- 숫자 사용 가능 범위
- 실제 적용 순서와 판단 조건
- 제외/불확실/충돌 내용

3~5개는 기획 기본값이다. 논문 수나 결론을 억지로 채우지 않는다.
핵심 주장과 수치는 전달받은 파일과 인용 위치를 다시 대조한다. 접근 불가라면 재검증 불가를 보고하고 검증된 표현으로 축소한다.

## 5. 카드별 문안 — 기본 중간 검토 지점
기본 6장. 대상과 주제에 맞게 5~8장 조정 가능.
순서는 질문 → 오해 교정 → 이유/근거 → 판단 요소 → 행동 → 요약을 출발점으로 삼되 기계적으로 고정하지 않는다.

한 장에 핵심 주장 1개. 제목 + 짧은 설명 2~3개는 편집 출발점이며 고정 글자 수 규칙은 아니다.
‘평가가 중요’만 반복하지 않고 무엇을·왜·어떤 행동에 연결하는지 설명한다.
각 카드의 실제 게시 문장, 남겨야 할 조건, C/S ID, 캡션으로 옮길 상세 내용을 기록한다.
제목도 의학적 주장이면 검증한다. 단순 질문이나 행동 유도 문장은 N/A로 표시할 수 있다.
그림 아이디어는 제안 가능하지만 이 단계에서 이미지 생성/최종 렌더링을 기본 실행하지 않는다.

사용자에게 문안 전체와 U ID 반영표를 보여준다. 이때 내용 수정 기회를 제공한다.
사용자가 ‘내용 확정, 디자인 진행’이라고 하면 해당 storyboard/brief 버전과 범위를 approval_log.md에 기록한다.
이는 본 패키지가 제안하는 내용 편집 절차이며 시스템상의 도구 승인 요구가 아니다.
사용자가 이미 디자인까지 진행하라고 명확히 허용했다면 이를 기록하고 반복 질문 없이 진행한다.

## 6. 디자인
이 단계에서 기존 DESIGN_SYSTEM.md와 실제 references/를 확인한다.
현재 레퍼런스 지침의 시각 규칙은 유지: 흰 배경, 검정 굵은 제목, 제한된 블루, 넓은 여백, 주제와 연결되는 사진/도식, 상단 로고·페이지 UI 없음.
기본 1080×1350 개별 PNG. 편집 가능한 코드 소스도 제공.
임상 검사의 경우 원문 Methods/Figure와 자세·랜드마크·장비를 대조한다.
밈은 공감에 필요한 장면에서만 사용하고 해부학이나 연구 증거를 대신하지 않는다.
원문 Figure 열람과 게시 재사용 권한은 별도로 확인한다.

디자인을 맞추기 위해 조건/수치를 조용히 바꾸지 않는다.
오타, 줄바꿈, 의미가 같은 축약은 재확정 없이 가능하고 기록한다.
효과/대상/처방/위험 등 의미가 바뀌면 관련 C ID와 카드만 다시 검증한다. 영향을 받는 문안만 재확정한다.
사용자가 해당 변경과 제작을 함께 허용했으면 그 범위 안에서 진행한다.

## 7. 출고 검수
의학: 원문 위치, 대상, 인과/관련, 단위, 조건, 제목의 과장.
내용: 사용자 의견 반영, 중복, 왜/무엇을 할지 누락, 쉬운 말.
시각: 원본+360px 축소, 텍스트 잘림, 내용/사진 대응, 임상 자세.
파일: 계획된 장수만큼 개별 PNG, 실제 해상도, 실제 소스·소재 존재.
출처: 사람이 클릭할 수 있는 DOI/공식 URL. 대화 전용 인용 토큰만 남기지 않는다.

기본 제공: exports 개별 카드, source, caption, 근거 기록, QA_REPORT.
자동 게시/외부 발송은 별도 요청이 있을 때만 한다.
